# Skill: code-review

## 何时使用
任务要求 review 代码 / 审查改动 / 检查实现质量时加载。

## 工作流
1. `git_diff()` 拿到当前改动全貌；改动为空则用 `read_file` 读目标文件。
2. 按下面清单逐条核对，每条给出「文件:行 → 问题 → 建议」。
3. 只报告**有依据**的问题，不给泛泛的"建议加注释"。

## 审查清单
- **正确性**：边界输入（空、负数、零、极值）、循环边界、返回类型是否与调用方期望一致；
- **错误处理**：异常是否被静默吞掉；错误信息是否指出了出错位置；
- **安全**：路径是否做了归一化与越界校验、是否有 `shell=True` 或字符串拼接命令、
  是否有 `eval` / `exec` 处理不可信输入；
- **可维护性**：是否存在重复逻辑、魔法数、命名与行为不符。

## 输出格式
```
[严重] path:line — 问题描述（为什么是问题）
[建议] path:line — 改进点
结论：<通过 / 需修改，附一句话理由>
```
